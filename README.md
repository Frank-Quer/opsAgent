# opsAgent

通过飞书私聊或群内 @ 调用本机 Codex，结合项目代码、shell、SSH 和已有工具排查问题，支持连续追问和进度卡片。

## 功能

- 群聊与私聊独立绑定工作区，按用户隔离会话。
- 管理员绑定与成员授权，支持撤销授权并取消当前任务。
- 按聊天设置默认环境、模型和思考强度，重启后保留配置。
- 读取引用消息、群历史与图片，在同一张卡片展示摘要和结论。

## 环境要求

- macOS 或 Linux；Go 版本以 [go.mod](go.mod) 为准，当前要求 1.26.3 或更高。
- 已安装并登录的 Codex CLI；原有集成验证版本为 `0.153.4`。依赖 `exec --json` 和 `app-server` 模型列表协议。
- 飞书企业自建应用，已启用机器人、长连接事件及相应权限。
- `make check` 需要 Make 和 Python 3；`service.sh` 另需 macOS 的 `caffeinate`、`pgrep` 和 `lsof`。

CI 配置覆盖 macOS/Linux；Windows 不在支持范围内。程序使用 Unix socket 和 Unix 进程组。

## 快速启动

在项目根目录执行：

```sh
go build -o bin/opsagent .
cp .env.example .env
chmod 600 .env
# 编辑 .env，填写应用凭据；首次绑定时将 FEISHU_ALLOWED_OPEN_ID 留空。
source .env
./bin/opsagent
```

程序不会自动加载 `.env`。飞书后台配置长连接，订阅 `im.message.receive_v1` 并发布应用后，由本人私聊发送 `/bind`，再发送 `/project set /项目绝对路径`。完成后可提问，使用 `/new` 开始新会话。

首次安装请按下方“飞书应用新建与配置”完成后台设置；配置文件位置和更多故障限制见 [使用指南](docs/usage.md)。macOS 可用 `./service.sh start` 和 `./service.sh stop` 后台运行；Linux 使用上述前台启动方式。

## 飞书应用新建与配置

以下流程适用于飞书企业自建应用。登录 [飞书开放平台开发者后台](https://open.feishu.cn/app)，使用有权创建应用的企业账号；若组织限制应用创建或敏感权限，需由企业管理员审批。后台菜单名称可能略有调整，可按括号中的事件或权限标识搜索。

### 1. 创建应用并启用机器人

1. 点击“创建企业自建应用”，填写应用名称、说明和图标，例如“排查助手”。
2. 进入应用，在“添加应用能力”中添加“机器人”，完成机器人名称、头像等配置并保存。
3. 在“凭证与基础信息”中找到 **App ID** 和 **App Secret**，供本地服务使用。App ID 通常以 `cli_` 开头。

本项目使用企业自建应用的机器人长连接，不使用群自定义机器人的 Webhook 地址。

### 2. 配置应用权限

打开“开发配置 → 权限管理”，按下表搜索权限标识，开通应用身份（tenant access token）对应的权限。以下按本项目的消息接收、发送、历史读取和图片下载功能列出；若后台提示权限替代关系或要求额外权限，以相应事件/API 的当前权限说明为准。

| 权限标识 | 本项目用途 | 何时需要 |
|---|---|---|
| `im:message.p2p_msg:readonly` | 接收用户发给机器人的私聊消息，包括 `/bind` 和管理命令 | 私聊必需 |
| `im:message.group_at_msg:readonly` | 接收群内 @ 机器人的消息 | 群内排查必需 |
| `im:message:send_as_bot` | 以机器人身份回复消息、发送帮助及排查卡片 | 必需 |
| `im:message:readonly` | 获取消息内容、引用消息和历史消息；配合消息接口权限要求使用 | 完整上下文功能 |
| `im:message.group_msg` | 读取机器人所在群中未 @ 机器人的消息 | 完整群历史功能，可能需要敏感权限审批 |
| `im:resource` | 下载消息中的图片等资源 | 图片分析功能 |

卡片使用消息回复和消息更新接口；请同时核对后台“回复消息”“更新应用发送的消息”“获取指定消息内容”“获取会话历史消息”“获取消息中的资源”各接口的权限说明。不要只订阅事件而遗漏其要求的权限。

本项目通过 `/whoami` 获取成员自己的用户 ID，通过群内 @ 或用户 ID 授权，不需要为此额外开通通讯录批量读取权限。

### 3. 填写本地凭据并启动服务

先安装并登录 Codex CLI，再在项目根目录执行：

```sh
go build -o bin/opsagent .
# 仅首次创建配置；已有 .env 时直接编辑，避免覆盖现有配置。
cp .env.example .env
chmod 600 .env
```

编辑 `.env`，把第 1 步获得的凭据填入对应变量：

```sh
export FEISHU_APP_ID='你的 App ID'
export FEISHU_APP_SECRET='你的 App Secret'
# 首次留空，随后由本人私聊 /bind 自动保存管理员 ID。
export FEISHU_ALLOWED_OPEN_ID=''
```

macOS 后台启动：

```sh
./service.sh start
```

Linux 或前台调试：

```sh
source .env
./bin/opsagent
```

保存飞书长连接配置时，本地服务需要保持运行并能访问飞书。macOS 启动成功会提示“飞书连接正常”；前台日志会出现“飞书长连接已就绪”。不要同时运行前台和后台两个实例。

### 4. 配置事件订阅与卡片回调

进入“开发配置 → 事件与回调”：

1. 在事件配置中选择 **使用长连接接收事件**，待本地服务连接就绪后保存。
2. 添加以下事件，按后台提示补齐事件所需权限。
3. 在回调配置中同样选择长连接方式，添加“卡片回传交互”回调并保存。

| 类型 | 标识 | 用途 |
|---|---|---|
| 事件 | `im.message.receive_v1` | 接收私聊和群内消息，所有消息命令都依赖此事件 |
| 事件 | `im.chat.member.bot.added_v1` | 机器人被加入群后自动发送帮助卡片；需要入群欢迎时订阅 |
| 回调 | `card.action.trigger` | 接收排查卡片“终止”按钮的点击；使用终止功能必需 |

长连接由本地服务主动建立，无需公网回调 URL、域名、HTTPS 证书或端口映射。`card.action.trigger` 属于回调配置，仅添加消息接收事件不能让按钮生效。

### 5. 发布应用并设置可用范围

1. 进入“应用发布 → 版本管理与发布”，创建版本，填写版本号和更新说明。
2. 设置应用可用范围，至少包含管理员本人及准备授权使用机器人的成员。
3. 确认机器人能力、权限、事件和回调配置已保存，提交发布。
4. 按企业规则完成管理员审核或免审发布，确认版本已生效；权限申请尚未通过时，相应功能仍不可用。

后续新增权限、事件或回调后，应再次按后台要求发布并完成审批。飞书的“应用可用范围”和本项目的 `/users` 授权是两层配置：加入可用范围后，成员仍需管理员通过 `/users add` 授权才能排查。

### 6. 绑定管理员并配置群

1. 在飞书客户端找到已发布的机器人，打开私聊，由本人先发送 `/bind`。收到“绑定成功”后，该用户成为管理员；首次绑定采用先到先得。
2. 若要私聊排查，发送 `/project set /本机项目绝对路径`，绑定机器人所在机器上的项目目录。
3. 把机器人添加到目标群。已订阅入群事件时，新加入会发送帮助卡片；已有群可发送 `@机器人 /help`。
4. 管理员在目标群发送 `@机器人 /project set /本机项目绝对路径`。私聊工作区不会自动应用到群。
5. 让成员私聊机器人发送 `/whoami`，管理员使用返回的 ID 发送 `/users add ou_...`；也可在群中发送 `@机器人 /users add @成员`。
6. 按需在群中设置 `/env set 测试环境`，再使用 `/models` 查看并选择模型及思考强度。

上述 `@机器人` 和 `@成员` 都需要在飞书客户端实际选择对象。完整命令及作用范围见下方“消息命令使用指南”。

### 7. 验收与常见问题

按以下顺序验证：

1. 私聊 `/whoami`、管理员 `/bind`、`/help` 均有预期回复。
2. 群中管理员或已授权成员发送 `@机器人 概述当前项目`，出现排查卡片，随后更新摘要和结论。
3. 收到结果后继续 @ 追问，再发送 `@机器人 /new` 验证新会话。
4. 引用一条文字或图片消息后 @ 提问，确认引用内容可读取；测试群历史时需有任务触发前的历史消息。
5. 在任务仍运行时，由发起人或管理员点击“终止”，确认卡片变为“已停止”，之后能够启动新任务。
6. 确认未授权成员、未 @ 机器人的普通群消息不会触发排查。

| 现象 | 检查位置 |
|---|---|
| 保存长连接配置提示未连接 | 本地服务是否运行、App ID/Secret 是否匹配当前应用、网络是否正常；macOS 查看 `.run/service.log` |
| 私聊无回复 | 机器人能力、应用发布状态及可用范围、私聊权限、`im.message.receive_v1` 订阅；未绑定前先发送 `/bind` |
| 私聊正常，群内无回复 | 机器人是否在群中、是否实际 @ 当前机器人、群 @ 权限是否生效、用户是否获授权、群是否绑定工作区 |
| 卡片有“终止”按钮但点击无效 | `card.action.trigger` 是否在回调配置中通过长连接订阅并发布，服务是否在线，操作者是否为发起人或管理员 |
| 引用、历史或图片读取失败 | 对应消息/群历史/资源权限及审批状态，机器人能否访问目标消息；仅有群 @ 接收权限不足以读取完整群历史 |
| 加群后没有帮助卡片 | 是否订阅入群事件并发布、机器人是否已绑定管理员；已有群不会自动补发，可手动 `/help` |

## 消息命令使用指南

以下命令在飞书聊天中发送。群内必须通过飞书的 @ 功能选中机器人，例如 `@机器人 /models`；私聊直接发送 `/models`。表中的参数需替换为实际值，`[思考强度]` 表示可选参数，不输入方括号。

### 谁可以使用

| 身份 | 私聊 | 群聊（须 @ 机器人） |
|---|---|---|
| 管理员 | 全部命令与排查 | 全部命令与排查 |
| 已授权成员 | `/help`、`/whoami` | 排查、`/help`、`/whoami`、`/new` |
| 未授权成员 | `/whoami`；尚未绑定管理员时可用 `/bind` | 不处理 |

管理员是首次成功 `/bind` 的用户，或启动配置中指定的用户。普通成员需要管理员授权，且群已绑定工作区，才能排查。项目、环境、模型及成员管理命令仅管理员可用，包括查看命令。

### 绑定与成员授权

| 命令 | 用途与示例 |
|---|---|
| `/bind` | 首次私聊绑定管理员；仅在尚未绑定时生效，不能覆盖或转让已有管理员 |
| `/whoami` | 查看自己的 `ou_...` 用户 ID；未授权用户也可私聊使用 |
| `/users` | 查看管理员与已授权成员 |
| `/users add @成员` | 授权一名成员；群内示例：`@机器人 /users add @张三`，两处 @ 均须实际选择对象 |
| `/users add ou_...` | 使用用户 ID 授权；可让对方先私聊机器人发送 `/whoami` |
| `/users remove @成员` | 撤销成员授权，也支持 `/users remove ou_...` |

成员授权适用于机器人所在的所有已配置群。撤销授权会清除该成员的会话并取消其当前任务；管理员不能添加或删除自身。授权名单重启后保留。

### 提问、追问与帮助

| 消息或命令 | 用途 |
|---|---|
| `@机器人 检查最近的报错` | 在当前群的工作区开始排查 |
| `@机器人 检查测试环境最近的报错` | 明确指定本次排查环境 |
| 回复文字或图片后发送 `@机器人 分析这个问题` | 分析引用内容；只引用并 @ 时默认分析被引用消息 |
| `@机器人 继续确认原因` | 沿用本人在当前聊天中的会话追问 |
| `/new` | 开始新对话，仅清空本人在当前聊天中的会话，保留工作区、默认环境、模型和思考强度 |
| `/help` | 查看简短帮助卡片，无需先设置工作区 |

管理员在私聊中提问时省略 `@机器人`。支持文本、富文本及图片，不解析普通附件、合并转发或卡片原文。单独 @ 且没有问题或引用时会提示补充问题。

### 项目工作区

| 命令 | 用途 |
|---|---|
| `/project` | 查看当前项目，显示目录名称 |
| `/project set /绝对路径` | 绑定机器人运行机器上已有的目录，例如 `/project set /Users/me/projects/api` |
| `/project clear` | 解除当前聊天的工作区绑定，清除该聊天的所有用户会话、默认环境、模型及思考强度 |

每个群绑定一个工作区，私聊独立绑定。路径含空格时直接输入完整路径，不加 shell 引号；不支持 `~` 或环境变量展开。未绑定或目录失效时不会启动排查。

切换到不同工作区会清除当前聊天中所有用户的会话及环境、模型、思考强度设置；设置为相同规范化目录则保留。

### 默认环境

| 命令 | 用途 |
|---|---|
| `/env` | 查看当前聊天的默认环境 |
| `/env set 环境名称` | 设置默认环境，例如 `/env set 测试环境`；需先绑定工作区 |
| `/env clear` | 清除默认环境，保留当前会话 |

环境名称为单行，最多 64 个字符。环境只是排查提示，具体连接信息由工作区指引或 skill 提供，不会设置系统环境变量。当前提问明确指定的环境优先于默认环境，且仅影响本次任务；引用消息和群历史不会自动覆盖环境。

### 模型与思考强度

| 命令 | 用途 |
|---|---|
| `/models` | 显示当前聊天设置的模型和思考强度，并列出可选模型、默认模型及各模型支持的强度；需先绑定工作区 |
| `/model` | 仅查看当前模型和思考强度；未设置时注明“跟随本机 Codex 配置” |
| `/model set 模型ID [思考强度]` | 设置模型，可同时设置该模型支持的思考强度；需先绑定工作区 |
| `/model clear` | 同时清除模型和思考强度覆盖，恢复本机 Codex 配置，保留会话 |

先发送 `/models`，再从返回列表中选择模型和强度。例如，列表中存在 `gpt-5` 且支持 `high` 时，可发送：

```text
@机器人 /model set gpt-5 high
@机器人 /models
```

`/model set 模型ID` 省略强度时，会清除此前设置的强度并恢复本机配置。强度以所选模型的 `/models` 列表为准，不支持的值会被拒绝；列表外模型不能设置。模型列表不保证当前提供者实际可调用全部条目，调用失败不会自动切换模型或重跑。

模型和强度按聊天保存：群内设置对当前群的后续排查生效，私聊设置仅对该私聊生效，不影响其他聊天，也不修改本机全局配置。更改模型和强度不会清空会话，连续追问会使用新的设置。

### 终止排查

运行中的排查卡片提供“终止”按钮，仅任务发起人或管理员可以点击。点击后取消当前任务及本地 Codex 进程组，卡片显示“已停止”并移除按钮；旧卡片不会误停新任务。已执行的操作不会回滚。

飞书后台须在事件与回调中订阅 **`card.action.trigger`（卡片回传交互）** 并发布配置，点击才会触发终止。终止通过卡片按钮操作，没有 `/stop` 消息命令。

### 生效范围与忙碌限制

| 设置或操作 | 生效范围 | 重启后 |
|---|---|---|
| 工作区、默认环境、模型、思考强度 | 当前群或当前私聊 | 保留 |
| 成员授权 | 当前机器人所有已配置群 | 保留 |
| 连续追问会话 | 当前用户、当前聊天、当前工作区 | 开始新会话 |
| `/new` | 仅本人在当前聊天中的会话 | 不改变持久设置 |

所有群和私聊共用一个执行槽位，任务最长 10 分钟。忙碌期间普通提问、`/new`、项目、环境和模型命令会被拒绝，不排队；请任务结束后重发。`/help`、`/whoami`、管理员的 `/users` 系列命令及卡片终止按钮仍可使用。

## 执行与授权边界

机器人复用本机 Codex 登录与工具配置，以 `--sandbox danger-full-access` 和 `-a never` 执行任务，可操作本机与 SSH 可访问的环境。请仅向可信成员授权，并按工作区规则明确任务权限。

- 首次 `/bind` 采用先到先得；也可在启动前设置管理员 `FEISHU_ALLOWED_OPEN_ID`。
- 同时仅执行一个任务，10 分钟超时；忙碌消息不排队，失败不自动重跑。
- 飞书凭据不传入 Codex 子进程；群历史和引用内容作为分析数据。
- 回复保密依赖提示词约束，不是程序强制过滤；本机 Codex 会话可保留原始上下文。
