# 使用指南

通过飞书机器人私聊或群内 @ 调用本机 Codex，直接使用 shell、SSH 和已配置工具排查各项目，并结合本机代码连续追问。具体操作按用户当前任务授权执行。

## 本机启动

依赖 Go 1.26.3 或更高版本（与 `go.mod` 一致）、已登录的 Codex CLI（已验证命令版本 `0.153.4`）、本机 SSH 及外网连接。在本项目目录构建启动；每个群及私聊分别通过消息命令绑定 Codex 工作区。

```sh
go build -o bin/opsagent .
cp .env.example .env
chmod 600 .env
# 在本机编辑 .env，填写应用凭据，首次保持 FEISHU_ALLOWED_OPEN_ID 为空。
source .env
./bin/opsagent
```

`.env` 不会由程序自动读取，需要先 `source`；它已被 Git 忽略。真实凭据不要填写到 `.env.example`。Codex 子进程不会继承 `FEISHU_` 环境变量。

macOS 日常使用可改用服务脚本（自动加载项目根目录的 `.env`，也支持已导出的环境变量）：

```sh
./service.sh start
./service.sh stop
```

脚本需要 `python3`，使用当前已构建的 `bin/opsagent`，通过独立进程会话后台运行并通过 `caffeinate -i` 防止闲置休眠，终端关闭后仍可运行；停止服务时防休眠自动解除。屏幕可熄灭或锁屏，建议接电并保持开盖。脚本不提供登录自启或崩溃自动重启。

重复启动不会创建新实例；也能关闭此项目目录中之前手动启动的机器人。日志写入 `.run/service.log`，每次启动清空。启动后若尚未确认飞书连接会提示检查日志，不自动重跑进程。更新代码后先构建，再执行 stop 和 start。

## 飞书后台

1. 创建企业自建应用并启用机器人能力。
2. 开通 `im:message.p2p_msg:readonly`、`im:message:send_as_bot`。
3. 启动本地服务，在事件与回调中保存“使用长连接接收事件”，订阅 `im.message.receive_v1`。
4. 发布版本并通过组织审核或免审，将本人加入可用范围。
5. 本人私聊机器人发送 `/bind`。首个成功请求会把用户 ID 原子写入项目 `.env` 并立即生效，无需重启；重启时通过服务脚本加载该文件。首次绑定采用先到先得，请由本人完成。
6. 先发送 `/project set /本机项目绝对路径`，再发送“概述当前项目”，收到回答后继续追问；发送 `/new` 开始新对话。

未绑定时只处理私聊文本 `/bind`，忽略群消息和其他内容，不调用 Codex。保存失败不会绑定；已有绑定不能通过 `/bind` 覆盖，本人重复发送会提示已绑定。`.env` 使用权限 0600 保存，保留其他配置；复杂或重复的绑定赋值会明确拒绝，需手动整理。绑定后管理员可私聊排查，授权成员可在已配置群排查；群聊必须明确 @ 当前机器人，未授权成员及未 @ 的群消息不执行。

## 用户授权

首次 `/bind` 绑定用户为唯一管理员，不能通过用户命令移除或转让。管理员可私聊发送命令，群内须 @ 机器人：

| 命令 | 用途 |
|---|---|
| `/users` | 列出管理员及授权用户 ID |
| `/users add @成员` 或 `/users add ou_...` | 授权用户在机器人所在的所有已配置群排查 |
| `/users remove @成员` 或 `/users remove ou_...` | 撤销授权并取消该用户当前任务 |
| `/whoami` | 返回自己的用户 ID，未授权用户也可私聊使用 |

普通用户不能查看或修改项目、环境、模型及用户名单；群内可排查、`/help`、`/new`、`/whoami`，私聊仅支持 `/help` 和 `/whoami`。管理员仍可私聊排查。管理命令与 `/whoami` 在忙碌时也可使用。群内 @ 目标必须是一名用户；直接 ID 按格式校验，不额外调用通讯录查询。

名单在用户配置目录 `opsagent/users.json` 按应用保存，文件权限 0600，目录 0700；损坏时启动报错，保存失败保持原授权。管理员绑定仍来自 `.env`。移除后清除该用户所有会话、取消本地任务及上下文读取，尽可能将卡片改为授权撤销提示，不再发送排查结果；已经执行的操作及已发送或发送中的消息无法回滚。

用户会话相互隔离，`/new` 仅清空本人当前会话；管理员切换群工作区时清空该群所有用户会话。

## 入群帮助

在飞书后台额外订阅机器人入群事件 `im.chat.member.bot.added_v1`，按后台要求开通事件权限并发布版本。机器人被拉入群后会自动发送静态帮助卡片，仅包含普通用户提问、指定环境、引用消息示例及 `/new`、`/help`、`/whoami`，不展示管理员配置命令；不要求邀请者是绑定用户，但未完成本人绑定时不发送。

本人可在群内发送 `@机器人 /help`，或私聊 `/help` 再次查看；无需设置工作区，忙碌期间也可使用，不影响排查任务。已有群不会因升级或重启补发。重复入群事件按事件 ID 去重，创建消息使用稳定 UUID（跨重启去重受飞书接口有效期限制）；退出后重新入群的新事件可再次发送。失败仅记录简短错误，不自动改发文本。

## 项目工作区

一个群绑定一个本机工作区，私聊独立绑定；只有已绑定的本人可设置，群内命令需要 @ 机器人。

| 命令 | 行为 |
|---|---|
| `/project` | 查看当前项目，仅显示目录名称 |
| `/project set /绝对路径` | 绑定已有本机目录，路径含空格时直接输入完整路径，不加 shell 引号 |
| `/project clear` | 解除绑定并清空当前会话 |
| `/new` | 开始新对话，保留项目绑定 |

切换项目会清空该聊天的旧会话；设置为相同规范化目录不清空。路径解析符号链接，不展开 `~`、环境变量或执行 shell 表达式。未绑定或目录失效时不会启动排查，也不会读取聊天历史。忙碌期间拒绝修改。

绑定保存在 `os.UserConfigDir()/opsagent/workspaces.json`（macOS 通常位于 `~/Library/Application Support/opsagent/`），按应用 ID 和聊天 ID 隔离。目录权限 0700、文件 0600，通过临时文件原子替换，保存失败保留原绑定与会话。配置损坏或不可读取时启动报错。重启保留绑定，但开始新对话。

升级后不会自动绑定旧项目，各聊天首次使用须设置工作区。已删除旧的独立 MCP、项目专用 SQL/SSH 封装及对应依赖；`opsagent mcp` 不再支持。项目排查知识由当前工作区的指引和已有 skill 提供。

## 群模型

绑定工作区后可用以下命令，群内需 @ 机器人，私聊独立设置：

- `/models`：读取当前工作区下 Codex 返回的非隐藏模型列表，标注接口报告的默认模型。
- `/model`：查看当前聊天的模型覆盖；未设置时跟随本机 Codex 配置。
- `/model set 模型ID`：从返回列表中选择模型，持久保存，仅影响当前聊天。
- `/model clear`：恢复本机 Codex 配置，不清空会话。

模型设置通过每轮 `--model` 传入，包括连续追问，不修改全局配置或提供者。切换模型和 `/new` 保留模型设置；切换或解除工作区会清除模型设置。命令仍仅本人可用，忙碌期间拒绝。列表使用短期 `codex app-server` 的 `model/list` 接口，20 秒超时，不执行排查任务，也不传入飞书凭据。

列表表示 Codex 报告的模型目录，不保证提供者实际可调用所有条目；自定义提供者的模型可能不在目录中，本版不接受列表外模型。模型调用失败不会自动换模型或重跑任务。模型参数兼容性和图片支持以所选模型与本机配置为准。

## 默认环境

先绑定工作区，再使用 `/env set 测试环境` 设置当前聊天的默认环境；`/env` 查看，`/env clear` 清除。群内须 @ 机器人，私聊独立设置，重启后保留。名称为单行、最多 64 个字符，首尾空白会去除。

环境只是每轮提示词，程序不维护连接信息、不检查 skill 中是否存在该环境，也不设置 shell 环境变量。请在工作区 skill 中维护具体环境信息。消息可直接写“检查生产环境最近的报错”：本人本次明确指定优先于默认环境，仅影响本次任务；引用和群历史不会自动覆盖环境。

修改默认环境保留会话，Codex 每轮须重新确认目标，不套用其他环境结论。未设置且本人未指定时，不沿用历史环境；项目指引无法明确目标时先澄清。切换或解除工作区会清除默认环境，设置相同工作区和 `/new` 则保留。忙碌期间拒绝环境命令。

默认环境与工作区保存于同一配置文件；兼容旧的纯路径绑定，下次保存时改为包含 `directory` 和可选 `environment` 的对象。保存失败保留原配置和会话。

## 群内引用与聊天上下文

把机器人加入群，在群内发送 `@机器人 检查这个问题`，也可以回复一条文字或图片消息后发送 `@机器人 分析原因`。只引用并 @ 时默认分析引用内容；单独 @ 会提示补充问题。支持文本、富文本及图片；不解析普通附件、合并转发或卡片原文。

- 每次群内触发读取触发前最近 10 条消息，直接引用单独标明并去重。Codex 可按需每页读取 20 条更早消息，不设历史时间下限；实际可见范围以飞书权限和接口为准。话题回复按已读取消息中的话题标识单独查询。
- 历史、引用和图片只是分析数据，不代表群成员授予操作权限。卡片仍只展示简洁摘要，不复述聊天原文或成员标识。
- 同群保留本人的会话，不同群及私聊相互隔离；群内发送 `@机器人 /new` 清空该群会话。所有会话仍共用一个执行槽位。
- 引用图片与当前消息中的图片自动传入，最多 5 张；历史图片和剩余图片按需获取。支持 PNG、JPEG、GIF，单张最多 20 MB；不支持的格式或读取失败会标明缺失并继续排查。
- `opsagent chat-context <socket> history [cursor] [thread_id]` 和 `opsagent chat-context <socket> image <message_id> <index>` 供 Codex 在任务内读取上下文。任务专属 Unix socket 由机器人进程持有飞书凭据，仅接受当前群、触发时间之前的历史和已读取消息中的图片；当前触发消息自带图片也可读取。临时目录权限 0700、图片 0600，任务结束后清理。进程被强制杀死时可能留下临时目录。
- 初始引用或历史读取失败不阻止任务；回答须说明证据缺失。机器人身份查询失败则启动报错，不猜测 @ 对象。

飞书后台需增加群内 @ 消息接收权限 `im:message.group_at_msg:readonly`。读取未 @ 机器人的历史消息还需申请群消息读取权限（通常为 `im:message.group_msg`），并满足获取消息、获取历史消息和下载消息资源接口所列的权限要求（如 `im:message:readonly`、`im:resource`，以后台当前接口权限页为准）。保留原有私聊和发送权限，继续订阅 `im.message.receive_v1`，发布新版本并完成审批后生效。代码仍只允许管理员或授权用户触发，不因开放历史读取而执行其他人的消息。

真实验收：普通群消息不触发、管理员与授权成员 @ 触发、未授权成员 @ 不触发、引用图片分析、最近历史和更早分页、同群追问及 `/new`，并确认摘要卡片回复在触发消息所在群。自动化测试不会修改飞书权限或向群发送消息。

## 行为与限制

- 回调快速返回，后台执行；初始排查卡片发送失败时不启动任务。
- 同时最多一个任务。忙碌期间的新消息（包括 `/new` 和 `/project`）不会排队，请收到结果后重发。
- 单任务 10 分钟超时，关闭服务时终止本地任务进程组；不自动重跑任务。
- 会话 ID 映射和去重记录仅存在内存。重启开启新对话，忽略启动前的消息；Codex 自身仍可保存会话历史。
- 每次排查使用一张卡片，按时间顺序显示最近三条摘要，旧摘要使用灰色辅助文字，最新摘要正常显示；连续相同的摘要不重复添加。最多每 3 秒刷新一次，即使没有新摘要，也循环更新标题指示点 `· / ·· / ···` 和累计耗时。实际显示节奏取决于网络及飞书客户端。
- 完成后停止动效，保留最近三条灰色过程摘要，最终结论在下方独立展示，默认 1～3 句；失败或超时同样保留灰色摘要并显示简短原因。最终回答不重复计入过程摘要。
- 不展示推理、命令、原始日志或查询明细。卡片更新失败时停止刷新但继续排查，最终以普通文本回复；最终更新失败或内容超出卡片限制时也用文本回复，超过 3000 字符分段。不会重新执行任务。
- 项目管理、忙碌提示及 `/new` 仍使用文本。失败或超时在卡片显示简短原因，不回传内部错误明细。
- 每轮提示词禁止回复密钥、凭据、连接串及服务器地址、主机名、域名、账号、端口和部署路径等具体信息；使用组件泛称。仅靠提示词约束，不做程序过滤，不构成强制保密保证。本机 Codex 会话仍保留原始上下文。
- 复用本机 Codex 登录和配置，遵循当前工作区的 `AGENTS.md`，按任务选择已有 skill；不再强制关闭其他工具、插件或覆盖 shell 环境，不修改全局配置。
- 新会话和续接会话均使用 `--sandbox danger-full-access` 与 `-a never`，允许直接执行本机 shell 和 SSH。已有本机配置和项目规则仍适用。
- 休眠或断网时不能及时处理；SDK 负责连接维护。断网后结果回复失败会记录本机日志，不会重做 Codex 任务。
- 平台回复错误日志仅包含错误码；Codex 错误不回传原始 stderr，以免把本机配置内容发到飞书。

## 验证

在项目根目录运行：

```sh
make check
```

该命令检查 Go 格式、执行 `go vet`、检查服务脚本语法、运行竞态测试并构建二进制。测试由 Python 施加 60 秒硬超时，使用模拟飞书接口和 Codex 子进程，无需凭据、不调用真实模型。

真实验收依次检查本人绑定、卡片创建、阶段摘要更新、最终结论、上下文追问及 `/new`。需确认飞书应用的卡片发送与更新权限；模拟测试不能替代真实权限和展示验收。

开发流程见 [贡献指南](../CONTRIBUTING.md)，项目概览见 [README](../README.md)。
